# `.agents`

Инструкции для ИИ-ассистентов и автоматизированных агентов, работающих с этим
репозиторием. Файлы здесь — источник правды для агентов, не зависящий от конкретного
ассистента. Ассистент-специфичные точки входа в корне (`CLAUDE.md`, `AGENTS.md`) ссылаются
на них, а не пересказывают: расхождение между копиями — дефект, а не вариант нормы.

| Файл                               | Назначение                                                   |
| ---------------------------------- | ------------------------------------------------------------ |
| [`conventions.md`](conventions.md) | Границы, которые нельзя нарушать, и как их проверить         |
| [`workflows.md`](workflows.md)     | Порядок работы: от задачи до коммита, включая шлюзы проверок |

Определения специализированных агентов с их границами и инструментами лежат в
`.claude/agents/`; вендоренные скиллы — в `.claude/skills/` (список и хеши закреплены в
`skills-lock.json`). Этот каталог описывает правила, те — исполнителей и справочники.

## Быстрый старт для агента

1. Прочитайте [`conventions.md`](conventions.md) — там перечислены границы, которые
   проверяются скриптами и сборкой, а не соглашением.
2. Прочитайте `CLAUDE.md` в корне — карта репозитория, команды и владение состоянием.
3. Следуйте [`workflows.md`](workflows.md) при внесении изменений.

## Главные правила

- **Доказательства вместо утверждений.** В отчёте приводите реальный вывод команд с
  числами (`pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build`), а не фразу «всё
  проходит».
- **Отрицательный тест должен ловить регрессию.** Убедитесь, что он падает при откате
  исправления, иначе он ничего не доказывает.
- **Не трогайте чужую незакоммиченную работу.** В репозитории может параллельно
  работать другой агент или человек; сначала проверьте `git status`.
- **Секреты не попадают в репозиторий, логи и отчёты.** `DATABASE_URL`,
  `MIXTURE_EDIT_TOKEN`, `MIXTURE_CLOUD_GITHUB_TOKEN` и любые ключи доступа облака живут
  только в переменных окружения и в `.env*`, которые игнорируются git.
- **Не ухудшайте дизайн-систему.** Новый интерфейс собирается из существующих токенов
  (`globals.css`), примитивов (`components/screenkit/primitives.tsx`) и shadcn-обёрток
  (`components/ui`), в моноширинном строчном стиле остального приложения.
- **Не жертвуйте функциональностью ради упрощения.** Улучшение — это исправление,
  расширение или ускорение существующего поведения; удаление возможностей требует
  отдельного решения человека.
