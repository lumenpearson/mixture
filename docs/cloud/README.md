# Облако · хранилище на приватном репозитории GitHub

Вкладка «облако» (настройки → облако, `?view=cloud`) работает с файлами как с облачным
диском: папки, загрузка перетаскиванием, предпросмотр, скачивание, переименование и
перемещение, удаление. Всё хранится в корне приватного репозитория
`lumenpearson/mixture-cloud` (переопределяется `MIXTURE_CLOUD_REPO`), каждое действие —
один коммит, история остаётся в git.

## Первый запуск

1. Откройте вкладку облака, нажмите «подключить» и вставьте GitHub-токен владельца
   (fine-grained PAT с правами `Contents: read and write` и, для первого раза,
   `Administration: write` или классический токен с `repo`). Токен хранится только в
   браузере.
2. Если репозитория ещё нет, появится карточка «репозиторий ещё не создан» — кнопка
   создаёт приватный репозиторий под вашим аккаунтом и кладёт в него `cloud.config.json`
   по умолчанию и папку `public/`.
3. Чтобы съёмочная группа видела приватные файлы без своих токенов, задайте на сервере
   (Vercel → Settings → Environment Variables) `MIXTURE_CLOUD_GITHUB_TOKEN` — токен с
   доступом к репозиторию облака; тогда посетители получают роли по ключам доступа из
   конфига, а операции с репозиторием выполняет серверный токен.

## `cloud.config.json`

Лежит в корне репозитория облака и версионируется вместе с файлами. Пример —
[`cloud.config.example.json`](cloud.config.example.json).

| Поле                           | Значение                                                                                   |
| ------------------------------ | ------------------------------------------------------------------------------------------ |
| `defaultVisibility`            | `private` (видят viewer и выше), `public` (все, если разрешено анонимам), `hidden` (владелец) |
| `rules[]`                      | `{ pattern, visibility }`; шаблоны как в `.gitignore`: `public/**`, `*.png`, `renders/ep0?/**`; последнее совпадение побеждает |
| `access.owners/editors/viewers`| GitHub-логины. Владелец репозитория и коллабораторы получают роль по правам репозитория автоматически |
| `access.allowAnonymousPublic`  | показывать ли публичные файлы без входа                                                    |
| `access.keys[]`                | `{ name, role, keyHash }` — ключ доступа без GitHub-аккаунта; хранится только sha256, сам ключ показывается один раз при создании во вкладке |

Роли: `anonymous < viewer < editor < owner`. Редактировать файлы могут editor и owner,
менять конфиг — только owner. Конфиг редактируется во вкладке (кнопка «доступ и
видимость») или прямо в репозитории.

Две тонкости правил видимости:

- **`hidden` наследуется вниз.** Шаблон без слэша (`secret`) совпадает с самой папкой и
  ни с чем внутри неё, поэтому правило «спрятать `secret`» прячет и её содержимое —
  иначе имя папки было бы скрыто, а файлы в ней читал бы любой viewer, угадавший имя.
  Правило, названное точнее (`secret/brief.pdf` → `public`), всё равно побеждает.
- **Папку видно по её поддереву, но спрятанную папку не «открывает» ничто.** Папка
  берёт самую разрешающую видимость своего поддерева, чтобы `public/**` оставляло саму
  `public` проходимой; если же папка попала в скрытое дерево, она остаётся `hidden`.
  Скрытая папка отвечает `not_found` и на список, и на любую правку внутри неё —
  editor не увидит и не тронет то, что предназначено только владельцу.

## Файловый менеджер

### Список

- Два вида: список и плитка. В плитке у изображений подгружаются миниатюры — лениво,
  только когда плитка подходит к экрану; object-url освобождается при размонтировании.
  У локального источника предпросмотр держит ровно один object-url: следующий файл
  освобождает предыдущий, отключение папки — последний, иначе просмотренная папка
  черновиков осталась бы в памяти вкладки целиком.
- Сортировка по имени, размеру, расширению и типу, по возрастанию и убыванию, с
  переключателем «папки сверху».
- Фильтры: категория файла (изображения, видео, аудио, документы, архивы, код, прочее) и
  видимость. Рядом с категорией показано, сколько таких файлов в текущем списке.
- Поиск: «в папке» фильтрует загруженный список, «везде» обходит весь репозиторий через
  `GetTree`. Обход дебаунсится, кэшируется на сессию (минуту на источник) и отменяется
  при выходе из режима; после любой правки кэш сбрасывается.
- `?path` и `?q` держатся в адресной строке, так что папку и поиск можно переслать
  ссылкой.
- Список рисуется страницами по 200 строк и растёт по мере прокрутки: папка на 2 000
  файлов не создаёт 2 000 узлов сразу.

### Клавиатура и контекстное меню

Строки — это `listbox` с roving tabindex: одна строка в порядке табуляции, остальные
достижимы стрелками.

| Клавиша                | Действие                                       |
| ---------------------- | ---------------------------------------------- |
| ↑ ↓ (← → в плитке)     | перейти по списку, с shift — расширить выделение |
| home / end             | в начало и в конец                              |
| enter                  | открыть папку или показать предпросмотр         |
| f2                     | переименовать на месте                          |
| delete / backspace     | удалить выделенное (с подтверждением)           |
| пробел                 | добавить строку в выделение или убрать          |
| ctrl/cmd + a           | выделить всё                                    |
| esc                    | снять выделение                                 |
| shift + f10, клавиша меню | открыть контекстное меню строки              |

Клавиша, нажатая на кнопке действия внутри строки, принадлежит кнопке: строка не
перехватывает её, иначе enter на «удалить» открывал бы предпросмотр.

«Скопировать ссылку» кладёт в буфер ссылку в приложение (`?view=cloud&path=…&open=…`),
а не `download_url` из GitHub: у приватного репозитория тот несёт временный токен в
запросе и всё равно протухает за минуты.

Правый клик открывает своё меню на строке, на пустом месте и на заголовке папки;
системное меню внутри менеджера подавлено. Пункты сгруппированы разделителями:
навигация (открыть, скачать, скопировать ссылку и путь), правка (переименовать,
переместить, дублировать, вырезать), организация (избранное, свойства) и опасное
(удалить). Меню пустого места добавляет «вставить», «выделить всё», «обновить» и
подменю сортировки и вида.

Выделение мышью — ctrl/cmd (по одному) и shift (диапазоном). При двух и более
выделенных появляется полоса групповых действий: копировать, вырезать, переместить,
удалить. Групповое скачивание архивом не делается.

### Загрузка

Очередь загрузки видна: путь, размер, состояние, ошибка и кнопки «повторить» и
«отменить» на каждом файле. Файлы отправляются по одному — GitHub делает коммит на
каждую запись, и параллельные записи в одну ветку дают конфликты, а не скорость.

- Можно выбрать файлы, выбрать целую папку (`webkitdirectory`) или перетащить папки —
  дерево раскрывается через `DataTransferItem.webkitGetAsEntry()` (до 2 000 файлов за
  одно перетаскивание).
- Если имя уже занято, файл ждёт ответа: «заменить», «оба» (получит имя `… (copy)`) или
  «пропустить»; при нескольких конфликтах есть «заменить все» и «пропустить все».
- Маршрут выбирается по размеру и по тому, есть ли у вас свой GitHub-токен:

| Условие                                       | Маршрут                                            | Предел |
| --------------------------------------------- | -------------------------------------------------- | ------ |
| файл ≤ 4 МиБ − 4 КиБ                          | `WriteFile` через сервер                            | 4 МиБ на всё сообщение (тело запроса на Vercel) |
| файл больше и в браузере есть свой токен      | `PUT` в contents API GitHub прямо из браузера       | ~90 МБ |
| файл больше, токена нет (только ключ)         | отклоняется, в очереди помечается «больше допустимого» | —      |

  4 КиБ запаса — не осторожность, а арифметика: лимит транспорта считает всё
  сообщение `WriteFileRequest`, а не только байты файла, поэтому файл ровно в 4 МиБ
  уходил в `resource_exhausted` на транспорте, не доходя до обработчика.

  Прямая загрузка отправляет ваш токен только на `https://api.github.com`, нигде не
  логируется и проходит те же проверки пути, что и сервер (`..`, `.git` в любом
  регистре, управляющие символы, `cloud.config.json`, длина ≤ 512). Права проверяет сам
  GitHub: токен без доступа на запись получает 403.

  Маршрут «напрямую» существует только у источника github: он PUT-ит в репозиторий
  облака, и для файлов с локального диска не предлагается вовсе.

### Настройки вида

Кнопка «файловый менеджер» в шапке вкладки открывает панель настроек. Она хранится в
`localStorage` под ключом `screenkit-cloud-settings-v1`: цвет по типу файла (и акцент
для каждой категории из палитры), миниатюры, папки сверху, плотность
(свободно/плотно) и вид по умолчанию (список/плитка). Избранное — локальные закладки на
пути, ключ `screenkit-cloud-favorites-v1`; в `cloud.config.json` оно не попадает, потому
что это личная заметка, а не право доступа.

## Потоковое воспроизведение

Приватный репозиторий не выдаёт публичных ссылок на файлы: `download_url` у записи
пустой, а `ReadFile` присылает файл одним сообщением до 4 МиБ и без перемотки. Поэтому
видео и аудио проигрываются через короткоживущий подписанный билет. Билет выдаётся на
любой предпросматриваемый файл, так что по нему открываются и картинки тяжелее
трёхмегабайтного предела `ReadFile`.

1. Предпросмотр просит `CloudService.CreateStreamTicket({ path })`. Сервер разбирает
   роль и видимость ровно так же, как в `ReadFile`: файл, который вам не виден, отвечает
   `not_found`, а не «нет прав».
2. Сервер подписывает `path|expires|sha` через HMAC-SHA256 и возвращает адрес того же
   origin: `/api/cloud/stream?p=<путь>&e=<срок>&v=<sha>&s=<подпись>`. Ни токена, ни
   ключа доступа в адресе нет — он попадает в DOM и в `referrer`, поэтому носить
   учётные данные ему нельзя. `v` — sha блоба: маршрут проверяет подпись, не обращаясь
   к GitHub, так что поддельный адрес не тратит наш лимит запросов.
3. `GET` (и `HEAD`) `/api/cloud/stream` сверяет подпись и срок `timingSafeEqual`,
   пересылает ваш заголовок `Range` в contents API GitHub с `Accept:
   application/vnd.github.raw` серверным токеном и отдаёт `206 Partial Content`. Если
   GitHub отвечает на `Range` целым файлом, маршрут сам режет поток на лету и всё равно
   отвечает `206` с `Content-Range` — в память при этом попадает один чанк, не файл.

Это **единственное** исключение из правила «все операции — RPC»: `<video>` открывает
запросы сам, не умеет слать заголовок `x-mixture-cloud-token` и требует `206`, чего
gRPC-Web не даёт. Разрешение на чтение выдаёт RPC, маршрут только проверяет билет.

| Переменная окружения          | Значение                                                                 |
| ----------------------------- | ------------------------------------------------------------------------ |
| `MIXTURE_CLOUD_GITHUB_TOKEN`  | обязателен: им маршрут забирает байты, и из него выводится ключ подписи   |
| `MIXTURE_STREAM_SECRET`       | необязателен: явный ключ подписи. Не задан — ключ выводится из токена облака с фиксированной меткой |

Без серверного токена билет не выдаётся: RPC отвечает `failed_precondition`, провайдер
возвращает `null`, и предпросмотр читает файл через `ReadFile` как раньше. Смена
`MIXTURE_STREAM_SECRET` мгновенно обесценивает все выданные билеты.

Ограничения потока: билет живёт 10 минут (браузер переиспользует его по паре
`путь + sha` и перевыпускает за минуту до конца); файл больше 100 МиБ — `413`;
испорченный, чужой и просроченный билеты одинаково отвечают `403`, чтобы разница не
подсказывала подбор подписи; неизвестный GitHub путь — `404`, сбой GitHub — `502`.
Ответ идёт с `Cache-Control: private, max-age=600` и `Content-Disposition: inline`, а
типы, которые браузер исполнил бы в нашем origin (`text/html`, `image/svg+xml`,
javascript), подменяются на `application/octet-stream`. Изменение правил видимости
догоняет уже выданный билет не сразу — в худшем случае через 10 минут.

Тот же список типов действует в предпросмотре: «открыть в новой вкладке» для
`blob:`-адреса такого типа отдаёт файл на скачивание, а не открывает вкладку.
Blob-адрес принадлежит нашему origin, и загруженная кем-то `logo.svg` со скриптом
внутри исполнилась бы рядом с токенами в `localStorage`.

## Устройство кода

| ------------------------------------------------- | ----------------------------------------------------------- |
| `components/screenkit/sections/cloud.tsx`          | рамка вкладки: статус, подключение, доступ, настройки        |
| `components/screenkit/cloud/provider.ts`           | интерфейс `CloudProvider`, реализация поверх `CloudService`, реестр источников |
| `components/screenkit/cloud/source-switcher.tsx`   | переключатель источников; при одном источнике не рисуется    |

| `components/screenkit/cloud/listing.tsx`           | список и плитка, roving tabindex, выделение, drag-and-drop   |

| `lib/cloud/file-types.ts`                          | расширение → категория → иконка и акцент                     |
| `lib/cloud/sorting.ts`, `lib/cloud/filtering.ts`   | порядок и фильтры (чистые, с тестами)                        |
| `lib/cloud/upload-queue.ts`                        | состояние очереди, выбор маршрута, конфликты (чисто, с тестами) |
| `lib/cloud/github-upload.ts`                       | прямой `PUT` в GitHub с прогрессом через XHR                 |
| `lib/rpc/cloud/config.ts`                          | схема `cloud.config.json`, роли и правила видимости (чисто, с тестами) |
| `lib/rpc/cloud/service.ts`                         | единственное место, где проверяются роль, путь и видимость; тесты — `service.test.ts` поверх заглушки GitHub |
| `lib/rpc/cloud/stream.ts`                          | билеты потока: подпись, проверка, сборка и разбор адреса, `Range` (чисто, с тестами) |
| `app/api/cloud/stream/route.ts`                    | `GET`/`HEAD` с `Range`; единственный не-RPC маршрут приложения |

Менеджер не обращается к RPC напрямую — только через текущий `CloudProvider`. Второй
источник (например локальные файлы поверх `lib/local/bridge.ts`) добавляется вызовом
`registerProvider` из своего модуля: файлы менеджера при этом не меняются. Смена
источника сбрасывает состояние менеджера — статус, список, путь, буфер обмена,
предпросмотр и очередь загрузки: маршрут и права одного хранилища не должны читаться,
пока показано другое.

`Status.message` несёт ключ словаря (`cloud.status.*`), а не фразу: интерфейс русский, а
прежний английский текст называл анонимному посетителю внутреннюю переменную окружения.
Карточка статуса показывает только известные ключи, остальное молча опускает; подробность
ошибки конфига остаётся в логах сервера.

## Ограничения

- Загрузка через сервер — чуть меньше 4 МиБ на файл: лимит тела запроса на Vercel
  считает всё сообщение, поэтому под конверт зарезервированы 4 КиБ. Со своим
  GitHub-токеном большие файлы уходят напрямую в GitHub, до ~90 МБ.
- Предпросмотр — изображения, видео, аудио, pdf и текст до 3 МБ; больше — по прямой
  ссылке. Видео и аудио идут потоком с перемоткой (см. «Потоковое воспроизведение»), до
  100 МиБ на файл.
- Перемещение папки и удаление папки — одним коммитом до 400 файлов.
- «Поиск везде» опирается на один обход дерева; на очень большом репозитории GitHub
  отдаёт его усечённым, и менеджер об этом предупреждает.
