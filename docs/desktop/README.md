# Десктоп · Windows-версия на Tauri 2

`apps/desktop` — это окно вокруг развёрнутого сайта. Интерфейс тот же самый Next.js-
проект, который живёт на Vercel; десктоп добавляет ровно одно, чего браузер не умеет
надёжно, — доступ к локальной папке на диске. Сборка выходит как `.exe`-установщик NSIS.

- продукт: `mixture · screenkit`, идентификатор `ru.mixture.screenkit`
- окно: 1280×800, минимум 720×560, обычная рамка Windows
- адрес: `MIXTURE_DESKTOP_URL` на момент сборки, иначе
  `https://mixture-codeilluminators.vercel.app`; в отладочной сборке —
  `http://localhost:3000`

Адрес зашивается в бинарник при компиляции (`option_env!`), поэтому у готового `.exe`
нет переключателя origin в рантайме: окно открывает ровно тот сайт, против которого его
собрали.

## Сборка на Windows

Нужны Node 22+, pnpm 10.34, Rust (stable, MSVC) и Microsoft Edge WebView2 (в Windows 11
он уже есть, в Windows 10 установщик подтянет его сам).

```powershell
pnpm install
pnpm --filter @mixture/desktop tauri build
```

Результат — `apps/desktop/src-tauri/target/release/bundle/nsis/*.exe`.

Чтобы собрать против другого стенда (превью Vercel, локальный сервер):

```powershell
$env:MIXTURE_DESKTOP_URL = "https://mixture-preview.vercel.app"
pnpm --filter @mixture/desktop tauri build
```

Разработка: `pnpm --filter web dev` в одном терминале и
`pnpm --filter @mixture/desktop tauri dev` в другом — отладочная сборка сама идёт на
`http://localhost:3000`. Корневой `pnpm dev` (`turbo run dev`) теперь поднимает обе
задачи сразу; для одного только сайта используйте `pnpm --filter web dev`.

Иконки в `src-tauri/icons` — временные, они рисуются скриптом без внешних зависимостей:

```bash
pnpm --filter @mixture/desktop icons
```

| --------- | ---------------------------------------------- | -------------------------------------------------------------------------- |

предупреждение SmartScreen при первом запуске.

## Доступ к локальным файлам

Вкладка «облако» умеет показывать локальную папку так же, как репозиторий облака.
Контракт один на все среды — `LocalFsBridge` (`apps/web/lib/local/bridge.ts`), а
реализаций три: браузерная (File System Access API), десктопная (команды Tauri) и
мобильная. Выбор делает `localBridge()` (`apps/web/lib/local/index.ts`): внутри оболочки
— Tauri, иначе браузер. `@tauri-apps/api` подгружается лениво, поэтому обычная вкладка
браузера его не скачивает.

Что видит пользователь:

1. Экран разрешения (`components/screenkit/local/permission-screen.tsx`) объясняет, что
   будет прочитано: имена, типы и — при открытии файла — содержимое.
2. Кнопка «выбрать папку» открывает системный диалог Windows. Выбранная папка
   запоминается в `local-root.json` в каталоге данных приложения, поэтому после
   перезапуска спрашивать заново не нужно.
3. Сразу после выбора идёт обход папки: количество файлов и подпапок, объём, топ
   расширений. Больше 5000 записей — сводка помечается как усечённая.
4. Кнопка «забыть» удаляет запомненный путь; «сменить» открывает диалог снова.
5. Если папка исчезла (отключённый диск, переименование), команда `local_permission`
   отвечает `prompt`, и экран разрешения возвращается.

### Границы

Каждая команда получает путь относительно выданной папки, в posix-виде. Перед любым
обращением к диску путь нормализуется и проверяется (`apps/desktop/src-tauri/src/local.rs`):

- `..`, пустые сегменты и `.` разворачиваются; выход выше корня — ошибка;
- сегмент с `:` (буква диска, NTFS-поток) или управляющим символом отклоняется;
- существующий путь канонизируется, и результат обязан начинаться с канонического корня
  — симлинк, ведущий наружу, отклоняется, а не разыменовывается;
- для ещё не существующего файла проверяется ближайший существующий родитель, поэтому
  запись через подменённую папку тоже не пройдёт;
- удалить саму выданную папку нельзя.

Наружу, в веб-вью, абсолютные пути не уходят — кроме одного случая: `local_stream_url`
возвращает абсолютный путь, который бридж тут же передаёт в `convertFileSrc`, чтобы
`<img>` и `<video>` читали файл через asset-протокол без копирования в память. Выданная
папка добавляется в область asset-протокола в рантайме (в `tauri.conf.json` она пустая:
на момент сборки папка ещё не известна).

Права окна перечислены в `src-tauri/capabilities/default.json`: ядро, `shell:allow-open`,
`dialog:allow-open`, файловая система в каталоге данных приложения, и список удалённых
адресов (`remote.urls`), которым разрешено вызывать команды.

### Команды

Имена ровно те, что перечислены в `TAURI_COMMANDS` (`apps/web/lib/local/bridge.ts`):

| Команда              | Аргументы            | Ответ                                        |
| -------------------- | -------------------- | -------------------------------------------- |
| `local_permission`   | —                    | `"granted"` или `"prompt"`                    |
| `local_request_root` | —                    | имя выбранной папки или `null` при отмене     |
| `local_forget_root`  | —                    | —                                            |
| `local_root_name`    | —                    | имя запомненной папки или `null`              |
| `local_scan`         | `maxEntries`         | `LocalScan`                                   |
| `local_list`         | `path`               | `LocalEntry[]`                                |
| `local_stat`         | `path`               | `LocalEntry` или `null`                       |
| `local_read`         | `path`, `maxBytes`   | байты (сырое ipc-тело, не массив чисел)       |
| `local_stream_url`   | `path`               | абсолютный путь для `convertFileSrc`          |
| `local_write`        | `path`, `content`    | `LocalEntry`                                  |

## Оболочка окна: панель, настройки, экран без сети

Три части десктопной оболочки живут на стороне сайта, а не в Rust: верхняя панель вместо
системного заголовка, карточка настроек окна и полноэкранный экран «нет сети». Все они
проверяют рантайм через `isTauriRuntime()` (`apps/web/lib/local/bridge.ts`) и вне Tauri
не рисуют ничего, поэтому веб-сборка остаётся прежней. `@tauri-apps/api/window`
импортируется лениво — внутри эффектов и обработчиков, — так что в браузере этот модуль
не загружается.

| Что                | Где                                                     |
| ------------------ | ------------------------------------------------------- |
| панель             | `apps/web/components/screenkit/desktop/titlebar.tsx`     |
| кнопки окна        | `apps/web/components/screenkit/desktop/window-controls.tsx` |
| работа с окном     | `apps/web/components/screenkit/desktop/use-window.ts`    |
| настройки          | `apps/web/components/screenkit/desktop/desktop-settings.ts` |
| карточка настроек  | `apps/web/components/screenkit/settings/desktop-settings.tsx` |
| экран без сети     | `apps/web/components/screenkit/offline-screen.tsx`        |
| состояние сети     | `apps/web/lib/net/online.ts`                              |
| строки             | `apps/web/lib/screenkit/i18n/desktop.ts`                  |

### Верхняя панель

Полоса высотой 40 пикселей (32 в компактном режиме) с названием приложения, текущим
разделом, необязательными часами и тремя кнопками окна: свернуть,
развернуть/восстановить, закрыть. Кнопки — обычные `<button>` с `aria-label` из словаря
и видимым фокусом: у окна без рамки нет системных кнопок, на которые можно опереться.
Закрытие подсвечивается цветом `--danger`.

Сама полоса и её пассивные дети помечены `data-tauri-drag-region`, поэтому окно тянется
за любое место панели, кроме кнопок. Двойной щелчок по региону разворачивает и
восстанавливает окно; обработчик сначала сверяет состояние окна с тем, каким оно было в
момент нажатия, — если оболочка Tauri уже переключила его сама, второе переключение не
отменяет первое.

Панель — обычный флекс-элемент над строкой «рельса + контент» в `app-shell.tsx`, а не
плавающий слой: строка ниже растягивается по `flex-1` и сама вычитает высоту панели, без
отступов и смещений. Высота дополнительно публикуется в `--sk-titlebar-h` на `<html>` —
её читает экран «нет сети», чтобы не закрывать кнопки окна. В `globals.css` переменная
равна `0px`, и на вебе перекрывать её нечем.

### Настройки

Карточка «десктоп» в разделе «оформление», после карточки плеера. В браузере она
показывает одну строку о том, что настройки живут в десктопном приложении, — вместо
переключателей, которым нечем управлять.

| Группа          | Настройка                            | По умолчанию |
| --------------- | ------------------------------------ | ------------ |
| окно            | поверх всех окон                     | выключено    |
| окно            | открывать развёрнутым                | выключено    |
| окно            | запоминать размер и положение        | включено     |
| окно            | минимальный размер                   | 720 × 560    |
| верхняя панель  | показывать панель                    | включено     |
| верхняя панель  | компактная высота                    | выключено    |
| верхняя панель  | сторона кнопок                       | справа       |
| верхняя панель  | часы                                 | выключено    |
| верхняя панель  | название раздела                     | включено     |
| верхняя панель  | акцентная линия                      | выключено    |

Всё это хранится в `localStorage` под ключом `screenkit-desktop-v1` и читается через
`normalizeDesktopSettings`: испорченное поле откатывается к значению по умолчанию
поодиночке, а неправдоподобная геометрия (окно меньше 320 пикселей по стороне или
координата за пределами любого монитора) отбрасывается целиком, чтобы окно не открылось
там, где до него не дотянуться.

«Поверх всех окон» применяется через `setAlwaysOnTop` при изменении и при запуске.
Размер и положение сохраняются по событиям `onResized`/`onMoved` с задержкой 400 мс и
восстанавливаются на старте через `setSize`/`setPosition` в логических пикселях.
Развёрнутое окно не запоминается: его прямоугольник — это монитор, и восстановить такое
окно как обычное значит открыть неразвёрнутое окно во весь экран.

### Экран без сети

`apps/web/lib/net/online.ts` держит состояние связи: `navigator.onLine` плюс события
`online`/`offline`, плюс проба доступности — `HEAD` на `/manifest.webmanifest` того же
origin, что и rpc-маршрут, с таймаутом 5 секунд. Проба идёт при старте, при событии
`online`, каждые 20 секунд, пока связи нет, и по кнопке «повторить». В Tauri она
повторяется ещё и каждые 60 секунд при живой связи: десктоп зависит от удалённого api,
и мёртвый сервер для него неотличим от обрыва.

Отсюда два вердикта, и разница между ними намеренная: в браузере оверлей реагирует
только на `navigator.onLine`, а недоступный сервер сам по себе офлайном не считается —
вкладка загружена и работает на встроенной библиотеке. В десктопной оболочке
недоступный сервер — это офлайн. Успешная проба важнее устаревшего `navigator.onLine`,
обратное неверно: обрыв связи сбрасывает результат последней пробы.

Оверлей закрывает всё ниже панели окна, показывает причину, кнопку «повторить» и
«продолжить без сети». Второй вариант убирает экран до конца сессии — встроенные вставки
и локальные файлы работают и без сети. Когда проба проходит, экран исчезает сам и
появляется тост «соединение восстановлено». Язык берётся из `screenkit-locale`, по
умолчанию русский; до монтирования компонент не рисует ничего, поэтому гидратация не
расходится.
